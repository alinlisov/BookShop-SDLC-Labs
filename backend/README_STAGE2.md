# Етап 2 — PostgreSQL та моделі даних

Збережіть власні зміни перед копіюванням. Скопіюйте в наявний проєкт файли з архіву, зберігши дерево папок. **Не видаляйте frontend!**

З кореня проєкту запустіть PostgreSQL у Docker Desktop:

```powershell
docker compose up -d postgres
docker compose ps
```

У каталозі `backend`:

```powershell
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
python -m app.seed
python -m uvicorn app.main:app --reload
```

Відкрийте http://127.0.0.1:8000/api/books — будуть три **демонстраційні** книжки. Для тестування у другому терміналі виконайте `python -m pytest -q`.

`backend/.env` не слід додавати до GitHub. У `compose.yaml` і `.env.example` пароль `change_me` є **лише локальним навчальним прикладом**; не використовуйте його на сервері. Для production слід використати унікальний пароль, керування секретами, міграції БД та реалізацію AES-256-GCM перед зберіганням реальних персональних даних.

**На цьому етапі** є тільки структури таблиць; реєстрація, замовлення, шифрування, ролі й відгуки ще не підключені до API. Не записуйте реальних персональних даних у базу до впровадження захисту. `create_all` створює відсутні таблиці, але не виконує міграцій наявних таблиць.
