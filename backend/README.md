# Інтернет-магазин книжок — backend (ЛР №4)

Цей backend є базовою структурою системи, що продовжує існуючий frontend на HTML/CSS/JavaScript.
Архітектура: frontend → FastAPI (REST API) → SQLAlchemy → PostgreSQL.

## Компоненти
- `app/database.py` — конфігурація БД, сесії та базовий ORM-клас.
- `app/models.py` — класи `User`, `Book`, `Order`, `OrderItem`, `Review` і зв'язки.
- `app/schemas.py` — схема відповіді API для книжок.
- `app/main.py` — запуск FastAPI, `/api/health` та `/api/books?search=...`.
- `app/seed.py` — повторюване початкове наповнення книжками без дублікатів.
- `tests/` — перевірки API, структури таблиць і зв'язків.

## Установлення на Windows (PowerShell)
1. Установіть PostgreSQL і створіть БД `bookshop` у pgAdmin.
2. У корені проєкту відкрийте термінал: `cd backend`.
3. Виконайте `py -3.11 -m venv .venv` (якщо середовища ще немає).
4. Виконайте `.\.venv\Scripts\Activate.ps1`.
5. Виконайте `python -m pip install -r requirements.txt`.
6. Скопіюйте `.env.example` у `.env`; укажіть пароль і параметри **власної** локальної БД. Не публікуйте `.env`.
7. Виконайте `python -m app.seed`.
8. Виконайте `python -m uvicorn app.main:app --reload`.
9. Відкрийте `http://127.0.0.1:8000/docs`, `/api/health`, `/api/books`.
10. Для тестів в іншому терміналі в каталозі `backend`: `python -m pytest -q`.

## Принципи організації та розподіл ролей
Модулі мають відокремлені відповідальності (розділення маршрутизації, моделей, схем і роботи з БД).
У навчальному одноосібному проєкті ролі бізнес-аналітика, дизайнера, frontend/backend-розробника та QA виконує одна людина на різних етапах. Для роботи з Git рекомендовані гілки `feature/database-models`, `feature/api-books` та `test/backend-smoke`, перевірка змін і злиття в `main`.

## Обсяг ЛР №4
**Реалізовано:** каркас backend, п'ять ORM-моделей, підключення до PostgreSQL, демонстраційні книжки, два маршрути та базові тести.
**Не реалізовано в межах ЛР №4:** реєстрація, повна авторизація, шифрування AES-256, обробка замовлень, відгуки через API, інтеграція frontend і production-розгортання. Ці частини заплановано на наступні лабораторні. Не зберігайте реальні персональні дані до реалізації безпеки.

`create_all()` не виконує міграції вже наявних таблиць; для подальшого розвитку доцільно використовувати Alembic.
