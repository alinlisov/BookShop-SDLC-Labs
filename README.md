# Інтернет-магазин книжок — BookShop

Навчальний вебпроєкт із дисципліни **«Життєвий цикл розробки програмного забезпечення» (ЖЦРПЗ)**. Розробка здійснюється послідовно: аналіз вимог, проєктування архітектури, планування Agile, створення базової структури коду, інтеграція компонентів і тестування.

**Поточний етап: лабораторна робота №4 — «Розробка базової структури коду».**

## Опис проєкту

Мета — створити вебзастосунок для перегляду й пошуку книжок, оформлення замовлень і роботи з відгуками. Система передбачає ролі гостя, зареєстрованого покупця та адміністратора.

В основі проєкту — наявний адаптивний інтерфейс інтернет-магазину на HTML, CSS і JavaScript. Для подальшого розвитку додано серверну частину на Python/FastAPI та реляційні моделі даних для PostgreSQL.

## Моделі даних

У `backend/app/models.py` описано п'ять ORM-моделей:

- **User** — дані облікового запису та ознака адміністратора;
- **Book** — назва, автор, жанр, ціна, обкладинка, наявність;
- **Order** — замовлення, дані покупця, сума, статус;
- **OrderItem** — книжка, кількість і ціна позиції замовлення;
- **Review** — текст відгуку та зв'язки з користувачем і книжкою.

Моделі містять зв'язки через зовнішні ключі. Поля для персональних даних передбачені структурою, але **саме шифрування, хешування паролів і механізми авторизації ще не реалізовано**. Не вносьте реальні персональні дані до завершення цих механізмів.

## Локальний запуск у Windows

### 1. Встановлення залежностей

Потрібні Python 3.11 та запущений PostgreSQL. Створіть базу даних `bookshop` через pgAdmin.

Відкрийте PowerShell у корені проєкту:

```powershell
cd backend
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Якщо `.venv` уже налаштоване й працює, створювати його заново не потрібно.

### 2. Налаштування PostgreSQL

Скопіюйте `backend/.env.example` у `backend/.env` та задайте рядок підключення:

```dotenv
DATABASE_URL=postgresql+psycopg://postgres:YOUR_PASSWORD@localhost:5432/bookshop
```

Замініть `YOUR_PASSWORD` на локальний пароль PostgreSQL. Спеціальні символи в паролі потрібно URL-кодувати. **Не завантажуйте `.env` до GitHub.**

### 3. Створення таблиць і тестових даних

У папці `backend`:

```powershell
.\.venv\Scripts\python.exe -m app.seed
```

Команда створює таблиці (якщо їх ще немає) та додає три демонстраційні книжки. Повторний запуск не повинен дублювати ці записи.

### 4. Запуск API

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

Адреси для перевірки:

- http://127.0.0.1:8000/api/health — перевірка працездатності API;
- http://127.0.0.1:8000/api/books — перелік книжок із БД;
- http://127.0.0.1:8000/api/books?search=Тестова — пошук за назвою;
- http://127.0.0.1:8000/docs — інтерактивна документація Swagger UI.

Наявний HTML-інтерфейс поки не повністю інтегровано із серверним API.

## Тестування

У папці `backend` запустіть:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

У лабораторній №4 підготовлено початкові тести API та ORM-моделей. Повноцінне компонентне, системне й нефункціональне тестування заплановане на лабораторну №6.

## Принципи організації коду

Використано багатошаровий підхід: представлення (HTML/CSS/JS), серверна логіка (FastAPI) та доступ до даних (SQLAlchemy/PostgreSQL). Розділено відповідальності за API, конфігурацію БД, моделі та валідаційні схеми. Це створює основу для подальшого застосування принципів SOLID під час реалізації бізнес-логіки.

## Ролі та організація роботи

Проєкт виконується індивідуально, з моделюванням ролей Agile-команди:

| Роль | Відповідальність |
| --- | --- |
| Business Analyst / Product Owner | Специфікація вимог, MoSCoW, пріоритети |
| UI/UX Designer | Структура та адаптивність інтерфейсу |
| Frontend Developer | HTML, CSS, JavaScript |
| Backend Developer | FastAPI, SQLAlchemy, PostgreSQL |
| QA Engineer | Тести, перевірка вимог і помилок |

Для планування задач використовується Trello. Для контролю версій — GitHub Desktop і GitHub. Окремі задачі можна виконувати у feature-гілках із подальшим переглядом змін перед злиттям у `main`.

## Подальші етапи

- **Лабораторна №5:** реалізація реєстрації та входу, захисту персональних даних, обробки й збереження замовлень, відгуків, адміністративних функцій та інтеграція frontend із backend.
- **Лабораторна №6:** модульні, компонентні, системні тести, перевірка FR/NFR, аналіз результатів і рекомендації.
